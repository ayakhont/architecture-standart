**Общее описание:**
- Требования изначально **не предполагают использование микросервисной архитектуры с применением Kafka** для обмена сообщениями между сервисами.
- Но по условию задачи менеджер проектов из команды цифровой трансформации определяет в какой последовательности команды должны делать
изменения в своих системах. Понять это **поможет архитектура MVP, которую я спроектировал ранее.**
- **Для обеспечения консистентности с уже спроектированной архитектурой MVP открытия депозита** 
я решил использовать микросервисную архитектуру и AccountService с Kafka из SB-ADR1.

**Описание решения:**
- Депозитные ставки хранятся в Account Service (базе Account Database MS SQL).
- AccountService публикует обновления ставок по депозитам в Kafka. Kafka используется для обеспечения надёжной и асинхронной доставки сообщений об изменениях ставок.
- Call Center Service подписывается на соответствующую тему Kafka и получает обновления ставок по депозитам.
- Integration Service подписывается на соответствующую тему Kafka и получает обновления ставок по депозитам.
- Для передачи файла, содержащего актуальные ставки по депозитам, используется Integration Service
- Integration Service формирует файл и передает его на SFTP сервер партнёрского кол-центра. Cохраняет запись об выгрузке в Integration Service Database.

### <a name="_bjrr7veeh80c"></a>**Альтернативы**
- Полный обмен через REST между сервисами без использования Kafka.
  - Плюсы: проще в реализации и отладке, широко распространённый подход.
  - Минусы: сложнее обеспечить надёжность доставки сообщений.
  - Причина отклонения: SB-ADR1
- Получение ставок по депозитам кол-центром напрямую из АБС, передача файла через SFTP без участия Integration Service.
  - Плюсы: упрощение архитектуры, меньше компонентов.
  - Минусы: превышение нагрузки на АБС, сложность обеспечения безопасности и контроля доступа.
  - Причина отклонения: SB-ADR1

**Недостатки, ограничения, риски**

- Увеличение сложности системы из-за введения микросервисной архитектуры и использования Kafka.
- Integration Service зависит от стабильности внешнего SFTP-канала.
